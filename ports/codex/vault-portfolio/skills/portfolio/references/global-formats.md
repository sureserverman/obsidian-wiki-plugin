# Global Roll-up Formats: `global-backlog.md` and `global-maturity.md`

`<vault>/Portfolio/global-backlog.md` and `<vault>/Portfolio/global-maturity.md` are regenerated
by `portfolio rebuild` from the registry and each enabled project's `backlog.md` and
`MATURITY.md` in its vault home. Neither file is edited by hand except for one section: the
`## Cross-project items` block in `global-backlog.md`. That is the only hand-edited content in
either file, and it is preserved byte-for-byte across every rebuild. Everything outside it is
overwritten.

## `<vault>/Portfolio/global-backlog.md` template

```
# Global Backlog

Auto-generated index of every per-project backlog in the vault Portfolio
tree. Edit the `## Cross-project items` section by hand; everything else is
regenerated by `$vault-portfolio:portfolio rebuild`.

**Last rebuilt:** <YYYY-MM-DD>

---

## Per-project backlogs

<one block per enabled project whose home backlog.md has entries, sorted by area then name>
### <area>/[[<name>]] — <COUNT> open
- **Path:** `<home>/backlog.md`
- **3 newest:** <comma-separated first three entry titles, or "none">

---

## Cross-project items

<!-- BEGIN PRESERVE — content below this line is preserved across rebuilds -->

<user-curated items; format mirrors the per-project BL-NNN style with GBL-NNN ids>

<!-- END PRESERVE -->
```

### Entry-counting rule

Real backlog files use three header conventions, and the counter tolerates all three:

1. **Canonical** (planning's `backlog` format): `## BL-NNN — title` (h2).
2. **Sectioned**: `### BL-NNN — title` (h3, usually under an `## Open` section).
3. **Legacy freeform**: `## <title>` (h2) with no `BL-NNN` id.

Counting procedure:

- Match `^#{2,3}\s+BL-\d+\s+—\s+(.+)$`: these are id'd entries (conventions 1 and 2). The dash
  must be an em-dash.
- If none match, fall back to legacy freeform: count `^##\s+` headers, **excluding** the
  structural headers `Backlog`, `Open`, `Closed`, `Done`, `Archive` and `Cross-project items`
  (case-insensitive).
- "3 newest" = the first three matched titles in file order (backlogs list newest first by
  convention), without the `BL-NNN — ` prefix.
- A project whose count is 0 gets no block.

The point of the fallback: never report `0 open` for a file that visibly holds entries.

### Preservation rule

On rebuild:

1. Read the existing `global-backlog.md`, decoding strictly as UTF-8.
2. Count the sentinels:
   - start: `<!-- BEGIN PRESERVE — content below this line is preserved across rebuilds -->`
   - end: `<!-- END PRESERVE -->`
3. **Exactly one of each, in order:** carry the body between them (sentinel lines excluded,
   outer blank lines trimmed) into the new file between fresh sentinels.
4. **Neither present** (first run, or a file someone stripped): write an empty preserved block.
   When the old file had content, warn on stderr that the sentinels were missing, and advise
   recovering curated items from a backup by pasting the body only, not the sentinel lines.
   Never guess or reconstruct lost content.
5. **Anything else** (duplicated pairs, a lone sentinel, out of order, or bytes that are not
   valid UTF-8): refuse. The file is left untouched, a warning names the counts, and the report
   says `SKIPPED (ambiguous PRESERVE)`.

The sentinels are HTML comments, so they are invisible in rendered markdown but unambiguous in
raw text.

## `<vault>/Portfolio/global-maturity.md` template

```
# Global Maturity Dashboard

Auto-generated from per-project MATURITY.md in the vault Portfolio tree.

**Last rebuilt:** <YYYY-MM-DD>

---

| Project | Docs | Sec | Pkg | UI/UX | i18n | Tests/CI | Ship-ready? |
|---------|------|-----|-----|-------|------|----------|-------------|
| <area>/[[<name>]] | <cell> | <cell> | <cell> | <cell> | <cell> | <cell> | ✅ yes / ❌ no |
...

---

**<N> projects tracked. <M> ship-ready.**
```

Only projects whose home holds a `MATURITY.md` get a row.

### Cell rendering rule

The axes are the `## Documentation`, `## Security`, `## Packaging`, `## UI/UX`, `## i18n` and
`## Testing & CI` sections. In each, the renderer counts checkbox lines: `- [ ]` and `- [x]` as
present, `- [x]` as ticked, `- [N/A]` as not applicable. A cell is:

- `🟢 t/p` when every present box is ticked;
- `🟡 t/p` when some are;
- `🔴 0/p` when none are;
- `⚪ N/A` when the axis has only `[N/A]` items;
- `⚪ –` when the axis is missing or empty.

A tick counts whatever follows it: `auto:`, `claim:` or a scope prefix are not parsed here.

### ship_ready rule

A project is ship-ready when **every** one of the six axes has all its present boxes ticked and
holds at least one box or one `[N/A]` item. A missing or empty axis is not ship-ready. Planning's
`project-maturity` skill applies its own per-axis thresholds when it answers the same question
for one project; this dashboard uses only the rule above.

## Cross-project id convention

Cross-project items in `global-backlog.md` use the prefix `GBL-` (Global BackLog) with
three-digit zero-padded numbers, `GBL-NNN`.

- The next id on any write is `max(existing GBL-NNN) + 1`, starting at `GBL-001`.
- Ids are never reused. Removing an entry does not free its number.
- The format otherwise mirrors the per-project `BL-NNN` style of planning's `backlog` skill:
  the same field set and layout, a different prefix.
- GBL entries are valid only inside the `## Cross-project items` preserve block. Never write a
  GBL id into a project's own backlog.

## Hard rules

- **Rebuilds are idempotent.** The same registry and the same per-project files produce the
  same content. A file is rewritten only when its content, ignoring the `**Last rebuilt:**`
  line, differs from what is there; otherwise the old file, date included, stays.
- **Never delete the PRESERVE block or its sentinels.** If they are entirely absent, they are
  written back with an empty body and a warning. Previously curated GBL items are never dropped
  silently.
- **An ambiguous file is refused, not rewritten.** This is a third outcome beside written and
  unchanged, and it is deliberate: the roll-up is regenerable, the curated block is not, and the
  vault has no version control behind it. **The refusal is scoped:** the other roll-ups and the
  sidecar pass still run. Duplicated pairs are the common case, because they are what pasting a
  recovered block back in, sentinels and all, produces.
- **Writes are atomic**: a temp file beside the target, then a rename, so an interrupted run
  never leaves a truncated roll-up.
- **Per-project order is by `area`, then `name`.**
- **Projects with `enabled: false` are excluded from both files.**
- **A project with no entries in its backlog has no block in `global-backlog.md`**, but it still
  has a row in `global-maturity.md` if it has a `MATURITY.md`. A project with neither
  contributes nothing.

## Evidence scope prefixes

`[x] auto:` evidence may carry a prefix naming the tree it resolves against: `repo:` (the
project's working tree) or `portfolio:` (the project's home, `<vault>/Portfolio/<area>/<name>`).
`portfolio:` exists because a security-audit tool can write its report under
`<home>/security/reports/` and nothing into the audited repo. `migrate` adds `repo:` to evidence
it carries over from the repo.

For rendering, both are ordinary ticks: the cell and ship-ready rules count `- [x]` lines and do
not parse the prefix. The full evidence syntax is planning's `project-maturity` skill's.
